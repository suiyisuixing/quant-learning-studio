# 四项完整演示脚本｜同一次练习，不拼页面

## 准备
核实运行站点/本地地址、本次HEAD、真实数据版本与许可、已审核论文、DeepSeek凭据和允许的调用预算。保护个人信息，使用获准演示账户。保留当前UI。

安排一条可在课堂完成的短历史练习，时长是演示安排而不是课程规定。不必现场下载全部行情或解析整本论文，可使用真实可溯源缓存；缓存时间和历史模式需明确。F2/F4本次实际请求各记录，不能只播放事先答案。

## 现场主线
|步骤|实际操作|观众应看到|核查线索|
|---|---|---|---|
|登录与首页|用本人测试账户登录，展示原有页面|仍是认可UI，四步清楚|实际HTTP、账户会话|
|F1 市场数据的显示|选择市场/对象/区间，切换一次，打开来源|数据、折线和范围确实变化；状态不是伪实时|snapshot_id、来源、as_of、数据类型|
|F2 人工智能的策划和分析|输入学习问题，请求分析；打开论文依据，改一个允许参数并确认|真实DeepSeek草案、出处、校验/用户确认|request_id、plan_id/version、approved_at|
|F3 模拟经营的沙盘演练|载入批准方案，开始；做一次配置调整或模拟买卖，推进时间，保存结果|虚拟资金、持仓、费用/风险和决策记录按操作变化|run_id、decision_id、result版本|
|F4 最后的人工智能分析问题与复盘|对刚才结果请求复盘，打开一条具体发现及论文依据|原计划/实际操作对照，非通用聊天；不确定处明确|review_id、plan/run/result和evidence关联|
|保存与重开|学生自己写一句心得，保存报告，退出再登录打开|内容和本次run对应，未丢失、未串账号|保存/重开真实结果|

若时间允许，改一项重要设置新建第二轮，比较两轮参数/结果/复盘；不得改写第一轮原计划或假装第二轮是未见过历史的新验证。

## 两项必须解释清楚
- F2是“还没做，先拟一个能执行的练习方案”；F4是“做过以后，分析真实操作和结果”。不靠一段相同回答换标题完成两项。
- 资金虚拟，但数据、计算、用户操作和AI调用的来源/状态必须真实标示。知识库增强是待验证能力，不承诺答案全对或必赚。

## 正式放行前的负例
未批准计划运行、改变参数沿用旧批准、重复点击、现金不足、无数据/过期、模型超时、论文停用、虚假引用、他人run/report访问、页面刷新/进程重启。测试结果独立留存，不强迫课堂现场展示所有负例。

## 故障和备用
网络故障可播放获准的历史录屏或打开已保存报告，并明确时间和“备用回放”。本轮未完成真实调用的项目仍写BLOCKED，不用录屏充当本轮LIVE通过。规则讲解、mock、合成市场和缓存AI都单独标记。

## 证据填法
用`templates/DEMO_EVIDENCE.md`分别填写F1—F4。附commit、运行环境、每步输入/操作/输出、引用或原始回执的脱敏位置。不要在公开GitHub上传密钥、原始私密聊天、联系方式或未授权论文/数据。

网站正常使用不能仅依赖所谓演示模式的隐藏成功逻辑；演示入口调用和普通用户相同的后端、身份验证和计算。
