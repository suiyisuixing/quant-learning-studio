# 项目计划

本计划覆盖完整产品要求，当前交付仅为仓库和协作初始化，不代表完成七人产品。认可源码与完整启动提示词仍待提供。十周阶段为相对项目周，当前实际日期由团队确认；不虚构已过去周次的成果。

## 阶段与验收

| 阶段 | 工作与依赖 | 交付/验收 |
|---|---|---|
| Bootstrap | 核实 owner、原始职责、源码与公开性；新公开仓库、规则、任务 | 公共文件和全推送历史检查；实际 CI/保护；缺项明确 |
| 第1–2周 | 本人账号核实，各写 PLAN；认可源码盘点；Yu 定稿接口；Xingze 界定案例和比较口径；三人建立资料卡 | 七份本人计划及批准范围；单一模块映射；数据/许可清单；无未授权 API |
| 第3周 | 根据认可设计明确流程与三项核心功能；完成接口样例及用户任务 | 可审阅原型、Checkpoint 1、输入输出合同；样本必须标注 |
| 第4–5周 | Zaixuan 账户与持久化/资料管理；Yu 确定性计算；Tianqi 接口适配与失败状态 | 模块单元/接口/负例测试，Draft 1；共享契约版本一致 |
| 第6–7周 | 知识检索/引用校验、学习进度与报告；跨模块集成 | 真实 HTTP 主流程；三功能集成；Checkpoint 2；无 API 时明确未运行 |
| 第8–9周 | 三名资料成员按原职责组织获准真人测试并记录问题；开发者修本人模块；RAG 对照 | 至少课程要求的真实用户测试和复测；独立保留开发/评估题；Checkpoint 3、Draft 2 |
| 第10周 | 集成回归、展示和资料交付；Yu 决定是否另行部署 | 当前 HEAD 的测试、使用说明、已知限制、演示视频/材料、最终报告；没有 URL 不声称上线 |

## 七个功能包与负责人

| 要求 | 负责人 / 合作 | 明确完成标准 |
|---|---|---|
| F01 账户、首页、继续学习 | Zaixuan；Tianqi 进度 | 服务端账户隔离、重启后持久化、无通用 admin 密码 |
| F02 案例与数据比较 | Xingze 内容；Yu 计算；Zaixuan UI | 来源和时间口径、数据校验/幂等、币种市场分离、不可比项说明 |
| F03 量化模拟与风险费用 | Yu | 不使用未来信息、现金持仓与费用守恒、可复现实验版本、合理对照 |
| F04 论文管理 | Zaixuan；Xingze 审核；三人材料 | 许可与审核状态、页码/hash、停用贯穿检索/缓存/导出，单一存储 |
| F05 检索后 DeepSeek | Tianqi；Zaixuan 资料接口 | 权限过滤、真实引用允许列表、数值一致、失败处理、最少必要外发 |
| F06 学习进度与报告 | Tianqi；Xingze 内容；Zaixuan UI | 真实提交决定进度，个人反思，持久化和账户隔离，安全导出 |
| F07 真人测试与问题 | Yifan / Guanjie / Yuntao；开发者修本人模块 | 同意、匿名、版本、复现步骤、实际结果、修复 PR 和复测；不虚构人数 |

完整细则以 requirements/01_PRODUCT_MASTER.md 为准，不能以本表删减要求。

## 首批可执行任务

1. 每个人阅读原始职责与总要求，提交自己的 PLAN-only PR。
2. Yu 核实成员公开账号与数字 ID，落实原源码，核对公开文件及历史，确定公共契约和实际代码路径。
3. Zaixuan 盘点认可 UI 的页面、账户/数据库/KB 管理边界；先提计划和 schema 需求。
4. Tianqi 提出资料检索、答案、进度和报告接口计划及无付费调用的失败测试策略。
5. Xingze 提出中美案例可比项、来源和审核方法的计划。
6. 三位资料成员分别提出本主题检索标准、资料卡输入输出、问答核验与真人测试计划；批准后再填写实际材料。

所有实施依赖计划批准；不把其他人的计划替写为本人承诺。产品实现不由初始化代理包办。

## 验证分层

协作规则测试、模块单元测试、fixture 验证、普通浏览器真实 HTTP、真实 DeepSeek、真人测试、部署验收各自记录。公开数据许可不等于允许发送第三方；没有 API 授权不作付费实验。展示收益和风险均来自确定性引擎，模拟效果不能冒充基金实绩。
