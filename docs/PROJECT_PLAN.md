# 完整项目计划｜R3 四项主线，UI保持

这是全量任务与依赖表，不是已完成的进度。M0—M5 仅表示依赖阶段，不安排周次、固定工时或逐周派工。每人一次领取完整个人提示词，连续完成本人全部实现/资料、验证和交接；已有授权不逐步重复确认。执行规则见 [成员全任务执行规则](../prompts/EXECUTE_TO_COMPLETION.md)。

## 产品目标
让入门者及想试不同策略的用户，用同一网站完成：
**F1 市场数据的显示 → F2 人工智能的策划和分析 → 用户确认 → F3 模拟经营的沙盘演练 → F4 最后的人工智能分析问题与复盘。**

原有中美案例、量化方法、论文知识库、学习和报告作为这条流程的内容及支撑。保留原前端，不重新立项，不因为week2宽泛主题自行换子题。七人职责以`docs/TASK_ASSIGNMENT.md`和最新`docs/TEAM_ROSTER.md`为准：4名开发者、3名非开发。

## 先贯通一个案例，再完成全部职责
用一组已审核的数据与论文、一个学习问题、一个可执行方案和一次用户操作贯穿四项。不是只演示F4；也不是先把所有市场和所有论文找齐才开发。首轮数据覆盖不足以完成中美研究时如实标注，之后补齐已选子题，不把一条技术流程当作所有研究验收。

## 并行安排
- 四位开发者分别开展数据/量化、UI/数据库、案例内容代码、DeepSeek检索；三位非开发成员找资料、核查引用、准备真人测试。未知Tianqi账号不阻塞其本地计划或其他成员。
- Zaixuan与Tianqi先对齐资料ID、时间字段、查询用途和回答存储；共用一套知识库。
- Yu给出计算和参数白名单；Xiangze给出可调用案例/教学内容服务；Tianqi负责两个AI阶段；Zaixuan负责原UI与存储。各作者修本模块bug，后三人不接代码修复。
- 依赖没接通时可以用注明的mock开发，不计为上游真实接通，不拿mock版去宣布四项全部可演示。

## 统一完成定义
代码已提交或资料已正式交接并保留作者、必要检查真实通过、上游集成有证据、他人按步骤可复查；四项整体须读`docs/DEMO_SCRIPT.md`与`templates/DEMO_EVIDENCE.md`。

单个成员可提交本人工作完成，但没有权限替其余功能标PASS；引用他人的证据要写对应commit/run，不能重新算作本人测试。课程与导师实际意见原样记录，本包不代为确认批准、不新增其他岗位。
