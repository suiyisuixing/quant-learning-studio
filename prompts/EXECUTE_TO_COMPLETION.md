# 成员全任务执行规则

用户最新要求：不安排周次，将本人全部任务一次给齐，沿同一份提示词连续执行到交付。这里的“一次完成”指任务范围完整、已授权步骤连续推进；不要求把多人依赖、真人操作或外部资源假装成一次 AI 回复即可完成。

## 开始后直接执行

1. 读取本人 `prompts/members/<姓名>.md` 的完整任务表、产品要求和实际源码。确定准确身份、当前 commit、实际可用工具与已有成果；不重复创建仓库，不用旧项目替换源码。
2. 把本人全部任务写入或补全 `plans/<role>/PLAN.md`，每项写清输入、输出、依赖、精确路径和验证。已有有效计划直接复用，不能只交一份泛泛建议就结束。计划覆盖完整职责，不只写第一个小模块。
3. 保留用户原定的首次范围批准：开发者的精确 PLAN 和路径由 Yu 确认；可信 main 未激活的实施范围不得自己改 policy 放行。批准已存在且覆盖当前内容时，直接按该范围继续，不逐步骤重复询问。未批准时先完成可交审的 PLAN、接口核对和既有代码检查；只暂停依赖批准的修改。
4. 在获准范围内，按“检查已有能力 → 实现缺口 → 验证 → 修复 → 联调 → 交付”持续推进。一个功能通过后接着做本人下一个任务；不要在第一张页面、第一个接口或第一份 PR 后宣布全部结束。可以用多个小提交/PR 保持可审查性，不能据此缩小完整任务范围。
5. 缺少队友接口时，记录明确的字段、版本、提供者和接入位置，继续独立部分。仅在单元/协议测试使用注明的 fixture/mock；正式运行不能静默退回 mock。公共入口、共享 schema、数据库迁移和依赖按原分工由 Yu/Zaixuan 整合，成员不各建一套系统。
6. 保留同一主线：F1 市场数据 → F2 演练前 AI 策划 → 用户明确确认 → F3 实际操作沙盘 → F4 操作/结果复盘。保留已认可 UI、框架及原有中美比较、因子研究、学习和报告能力。
7. 每完成一项，在本人交付记录中填真实状态与证据。全部任务成功或明确受外部条件阻塞后，汇总一次完整交付；未解决缺口列出具体所缺输入和负责角色，不能用“后续完善”隐藏必要功能。

## 三位资料测试成员的执行方式

Yifan、Guanjie、Yuntao 都完成“认领去重 → 查找并阅读资料 → 来源卡与原文核查 → 学生问题/参考要点 → F1–F4 真人操作 → 问题记录 → 修复后复测 → 文件交接”全套任务，不拆成三个固定专业岗位。

AI 可搜索核对公开来源、整理文档、准备测试步骤和汇总已提供的真实记录；真人参加、实际操作、同意与个人心得必须来自本人/参与者。没有这些输入时，继续其余可做的资料工作，并把相应真人步骤标为待进行。不得替他们写代码、爬虫、自动化测试、CI 或部署，也不要求 GitHub/Fork。

## 共同边界

- 正常开发沿用本人 Fork/任务分支和 Yu 最终合并；不授予主仓库 Write/Maintain/Admin，不发送未核实邀请，不伪造自审或成员身份。
- 只操作本项目。保留已有变更及他人贡献；源码公开与公网部署分开，本次不买服务、不擅自付费调用、不发布网站。
- 没有真实数据许可/模型授权时，只暂停相关真实验收；缺账号不猜，缺资料不编。工具无法读写或运行时如实记录，不能声称创建/测试成功。
- 公开前检查文件及历史；不提交密钥、数据库、受限全文/切片/索引、无许可行情和原始个人记录。资料原作者、核查者、实际代录者分别登记。
- 运行代码、离线 fixture、真实 HTTP、真实模型、真人使用、视觉检查是不同证据；结果绑定本次 commit，不能复制旧报告冒充当前测试。

## 一次完整交付应包含什么

开发者：本人全部任务的状态表、代码与必要测试、精确 commit/PR、接口输入输出、当前真实验证、交接对象及仍受阻事项。资料成员：本人认领清单、逐项核查的资料卡、独立的评测参考要点、匿名真人操作/问题/复测记录及交付说明；无需代码 PR。

完成标准来自本人提示词和 `docs/FOUR_FEATURES.md`。工作记录使用现有模板，实际每项状态为 TODO / IN_PROGRESS / DONE / BLOCKED；未经执行不能预填 DONE，单人模块通过不能替全站 F1—F4 宣布通过。
